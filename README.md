# Merge Prom Feed — злиття фідів постачальників у YML для Prom.ua

Скрипт `merge_feeds.py` завантажує XML-фіди кількох постачальників,
зіставляє товари за артикулом (SKU) і формує **два окремі** YML-файли для
функції Prom.ua **"Автоматичне оновлення каталогу за посиланням"**:

| Файл | Поля | Коли оновлюється |
|---|---|---|
| `merged_feed.xml` (файл залишків) | `id`, `available`, `quantity_in_stock` | **щодня автоматично** (GitHub Actions) |
| `price_feed.xml` (файл ціни) | `id`, `price`, `currencyId` | **вручну**, коли ви самі вирішите оновити ціни |

Жоден із файлів не містить назв, описів, зображень чи категорій — тільки
поля, потрібні для оновлення вже існуючого товару за артикулом, щоб не
зачепити структуру папок на сайті (детальніше — у коментарі на початку
`merge_feeds.py`).

На Prom.ua ці два файли підключаються як **два окремі джерела** для
автооновлення каталогу за посиланням: одне з розкладом "щодня", інше —
запускається вами вручну кнопкою "Оновити зараз" у налаштуваннях
відповідного джерела (або взагалі не за розкладом, якщо Prom вимагає
розклад — виберіть там найрідший, наприклад "раз на місяць", і оновлюйте
фактично тоді, коли самі перезапустите workflow нижче).

---

## 1. Перевірка локально (необов'язково, але дуже бажано)

```bash
pip install -r requirements.txt

# Спочатку подивіться, як саме влаштовані фіди постачальників:
python merge_feeds.py --inspect
```

Скрипт підтримує прапорець `--mode`:

```bash
python merge_feeds.py --mode stock                  # тільки залишки/наявність (за замовчуванням)
python merge_feeds.py --mode price                  # тільки ціна
python merge_feeds.py --mode both                   # обидва файли за один запуск

# Можна також вказати свої шляхи/назви файлів:
python merge_feeds.py --mode stock --output merged_feed.xml
python merge_feeds.py --mode price --price-output price_feed.xml
```

`--inspect` завантажить кожен фід і покаже:
- кореневий тег документа;
- скільки товарів знайдено;
- сирий XML першого товару;
- що саме скрипт розпізнав як SKU / ціну / кількість.

Якщо для якогось постачальника результат порожній або поля розпізнані
неправильно — відкрийте `merge_feeds.py` і додайте реальну назву тега
у відповідний список на початку файлу: `SKU_TAGS`, `PRICE_TAGS`,
`QTY_TAGS` або `AVAILABLE_TAGS`. Це рядки виду:

```python
SKU_TAGS = ["vendorCode", "vendor_code", "sku", "article", ...]
```

Просто допишіть туди потрібну назву тега — і запустіть `--inspect` ще раз.

Коли все розпізнається правильно:

```bash
python merge_feeds.py --output merged_feed.xml
cat merged_feed.xml
```

## 2. Розгортання на GitHub Actions (щоденний автозапуск + постійне посилання)

### Крок 1. Створіть репозиторій на GitHub

1. Зайдіть на [github.com](https://github.com) → **New repository**.
2. Назвіть його, наприклад, `prom-feed`. Публічний чи приватний — не
   принципово (Pages працює для обох на платних планах; на безкоштовному
   плані GitHub Pages для приватних репозиторіїв недоступний, тож якщо
   плану Pro немає — зробіть репозиторій **публічним**; сам XML-фід з
   цінами не є секретною інформацією).
3. Не додавайте README при створенні — завантажите файли вручну (крок 2).

### Крок 2. Завантажте файли проєкту

Найпростіше — через веб-інтерфейс:

1. Відкрийте створений репозиторій → **Add file → Upload files**.
2. Перетягніть туди `merge_feeds.py`, `requirements.txt`, `README.md`,
   а також папку `.github` цілком (усередині два файли:
   `update-feed.yml` — щоденне оновлення залишків, і `update-price.yml` —
   ручне оновлення ціни; GitHub коректно збереже вкладену структуру папок
   при перетягуванні).
3. Натисніть **Commit changes**.

*(Альтернатива для тих, хто звик до git: `git init`, `git add .`,
`git commit -m "init"`, `git remote add origin <URL репозиторію>`,
`git push -u origin main`.)*

### Крок 3. Увімкніть права на запис для Actions

1. У репозиторії: **Settings → Actions → General**.
2. Прокрутіть до розділу **Workflow permissions**.
3. Виберіть **Read and write permissions**.
4. Натисніть **Save**.

(Без цього кроку workflow не зможе закомітити оновлений `merged_feed.xml`
назад у репозиторій.)

### Крок 4. Увімкніть GitHub Pages — це і дасть постійне посилання

1. **Settings → Pages**.
2. У полі **Source** виберіть **Deploy from a branch**.
3. Branch: **main**, папка: **/docs**.
4. **Save**.

Через 1–2 хвилини GitHub покаже базову адресу Pages, і у вас з'являться
**два постійні посилання** (файли ще не створені, але посилання вже можна
буде вставляти в Prom — вони "запрацюють", щойно ви вперше запустите
відповідний workflow, крок 5):

```
https://<ваш-логін>.github.io/<назва-репозиторію>/merged_feed.xml   ← залишки/наявність (щодня)
https://<ваш-логін>.github.io/<назва-репозиторію>/price_feed.xml    ← ціна (вручну)
```

Перше посилання вставляєте в Prom.ua як джерело для автоматичного
оновлення наявності/залишків, друге — окремим джерелом для ціни.

### Крок 5. Перевірте обидва workflow вручну

1. Вкладка **Actions** у репозиторії.
2. Зліва є два workflow: **Update Prom stock feed (daily)** і
   **Update Prom price feed (manual)**.
3. Відкрийте перший → праворуч кнопка **Run workflow → Run workflow**.
   Дочекайтесь зеленої галочки (20–40 секунд) і перевірте, що з'явився
   `docs/merged_feed.xml`, а посилання на нього відкривається.
4. Так само запустіть вручну **Update Prom price feed (manual)** —
   з'явиться `docs/price_feed.xml`.

Після цього:
- **файл залишків** оновлюватиметься сам щодня за розкладом
  (`cron: "0 3 * * *"` у `.github/workflows/update-feed.yml`);
- **файл ціни** НЕ оновлюється сам ніколи — тільки коли ви зайдете у
  вкладку Actions і власноруч натиснете **Run workflow** на
  **Update Prom price feed (manual)**. Це і є той "ручний" режим
  оновлення ціни, який ви просили.

## 3. Про точний час запуску (06:00 за Києвом)

GitHub Actions планує завдання за UTC, без урахування переходу на літній
час. Поточний `cron: "0 3 * * *"` (03:00 UTC) дає:

- **влітку** (діє UTC+3, EEST) → приблизно **06:00** за Києвом;
- **взимку** (діє UTC+2, EET) → приблизно **05:00** за Києвом.

Якщо вам критично, щоб було рівно 06:00 цілий рік, є два варіанти:

**Варіант А (простіше):** двічі на рік (наприкінці березня й жовтня,
коли Україна переходить на літній/зимовий час) відкрити файл
`.github/workflows/update-feed.yml` і замінити `"0 3 * * *"` на
`"0 4 * * *"` (взимку) або назад на `"0 3 * * *"` (влітку).

**Варіант Б (автоматично, складніше):** додати в workflow два
`cron`-записи (`"0 3 * * *"` і `"0 4 * * *"`) і на початку job перевіряти
поточну дату — чи це період літнього часу в Європі — виходом з кроку
(`exit 0`), якщо запуск "зайвий". За потреби можу одразу написати такий
варіант workflow.

Також завжди можна запустити оновлення вручну в будь-який момент кнопкою
**Run workflow** (крок 5 вище) — наприклад, якщо потрібно оновити ціни
терміново, не чекаючи розкладу.

## 4. Додавання нового постачальника в майбутньому

Відкрийте `merge_feeds.py`, знайдіть список `SOURCES` на початку файлу
й додайте новий елемент:

```python
{
    "name": "новий_постачальник",
    "url": "https://.../feed.xml",
    "priority": 4,  # менше число = вищий пріоритет при однаковому SKU
},
```

Запустіть `python merge_feeds.py --inspect`, щоб перевірити, чи коректно
розпізнаються поля для нового постачальника (див. розділ 1).

## 5. Структура репозиторію

```
.
├── merge_feeds.py                      # основний скрипт
├── requirements.txt                    # залежності (requests)
├── README.md                           # цей файл
├── docs/
│   ├── merged_feed.xml                 # залишки/наявність — оновлюється щодня автоматично
│   └── price_feed.xml                  # ціна — оновлюється тільки вручну
└── .github/
    └── workflows/
        ├── update-feed.yml             # щоденний автозапуск файлу залишків
        └── update-price.yml            # тільки ручний запуск файлу ціни
```
